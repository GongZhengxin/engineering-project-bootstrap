# 工程启动

默认在当前项目根目录完成一次只读接管，直接在聊天交回。用户只说“准备开发”时，做到可复现的工程基线和下一项验法即可。安装依赖、生成入口、首次提交、写工单、实施、向模型发送材料各依本次授权。已有授权沿用其范围。

## 发现项目事实

1. 定位实际工作目录、Git 根和目标组件；读取生效的 AGENTS.md、AGENTS.override.md 或项目指定入口，沿链接找权威需求、任务源、验收与测试说明。分清仓库中的事实、外部系统链接和旧快照。外部任务系统不可访问时注明缺口。已有工作约定直接沿用；缺任务系统的小项目可用聊天中的一句验收约定。
2. 用只读文件枚举和搜索（如 rg --files，兼顾 CI 等隐藏入口）找到源码、调用者、子包、包清单、锁文件、运行时版本、构建脚本、CI 工作目录与测试用例。检查与任务相关的未提交、未跟踪和暂存工作。Git 可用时用 git --no-optional-locks status --short --branch 和具名 diff。无 Git 时读目录本身。跳过凭据、会话库、依赖缓存、生成物及无关目录。
3. 从 README / CI 的命令追到实际脚本、锁与用例，注明执行目录及证据路径；存在冲突时检查当前分支的调用链。检查 shell、解释器或包管理器版本和必要的本地输入。命令可识别但尚缺环境、数据或授权时，给出具体缺项。对可信且能隔离输出的小基线实际运行并记录命令、退出码及失败原因；预先读安装钩子和运行脚本，涉及写源文件、联网、设备或部署时按项目边界办理。临时输出使用新的受控路径，结束后核工作树与入场时一致。

## 选择已有工作流

按用户要交付的结果选择，在当前会话的 Skills 目录按名称打开对应 SKILL.md，再跟其引用。根据实际需要组合；仓库存在、目录为空或盘上有图片，都不足以单独判定用户意图。

| 任务证据 | 首选 Skill | 组合情形 |
|---|---|---|
| 有新目标，要从需求定义行为和成功条件 | build-from-requirements | 空目录尚无需求时，先记录缺少的最小用户动作或成功结果 |
| 已有行为、调用者或数据要接管、修复或兼容扩展 | change-existing-software | 既有软件增加未定义的新能力，补用 build-from-requirements |
| 用户指定以某界面、截图或录屏为可观察目标 | rebuild-from-reference | 已有宿主加参考交互，同时读 change-existing-software；标明视口、状态和看不到的交互 |

缺少所选 Skill 时给出名称和恢复方法，继续可独立完成的检查。仅有静态参考时可以核对外观，真实交互保留待验。

## 分工和接续

Codex 负责路由、技术判断、运行基线、核候选差异和最终签收。准备阶段可直接本地完成。需要普通模型协作时读所选工作流的协作说明，并核当前项目允许的 DSH ACP 入口。只记录可披露的能力与许可结果，配置和密钥留在工位。

- DeepSeek 适合边界明确、有可执行验法的实现或修复，仅获该项任务的必要输入和隔离写域。Gemini 适合独立视觉审阅或基于已核数据的说明；默认只读。涉及视觉时核获准图片字节的送达和具体回答。
- 拟派工先核授权人/任务、模型与推理档、允许出站材料、可执行的请求上限及绝对截止、工具和写域。用项目已有控制器；缺项则标记相应角色待准入，Codex 继续能做的部分。不要用其他 API、个人账号或聊天中自称的权限补位。
- 交接点记工作区、盘上基线（含必要的未提交输入）、候选差异、已跑入口、失败与余额。中断先在本机对账原角色、会话、已执行动作与候选，沿同一授权和剩余额度恢复。恢复依据缺失时封存部分成果。请求失败与内部重试计入出站预算；费用或 token 硬限单独验证。正式接收由 Codex 对同一候选复跑入口、核差异及遗留风险。

## 交回

用简短中文列出所选流程及理由、有效入口和工作目录、实际检查与缺口、各角色当前可做的事、下一项可观察验收。需要补项目入口时先列最小相对路径差异，只链接已有事实来源。项目文档、任务系统和机器 Profile 均按原有归属维护。
